# Playground 视觉重构（纸感 · 便利贴 · 产品/实验室分层）

- **状态**：实现中（空态骨架 / 暗色纸 / Sonner / Slider / IoTracer 进调试）
- **性质**：**视觉与信息架构重构**——不改 pipeline / STT / LLM / 声纹算法行为
- **范围**：`apps/playground` + `packages/ui`（design tokens、shadcn 组件补齐、可复用产品组件）
- **关联**：
  - [MVP spec §2.7](./live-reply-coach-mvp.md)（playground 角色）
  - [桌面 Island 头脑风暴](../brainstorm/2026-07-24-desktop-island-and-reply-stickies.md)（正式桌面壳愿景；**本轮不做**）
  - Grill 决议：产品主舞台 + 实验室；黄色品牌；纸感；通知中心式候选列
- **作者**：路路（grill 对齐后整理）

## 0. 一句话

把试用场从「能跑的灰盒表单墙」重做成 **纸感、品牌黄、产品级主舞台**：Live 以黄色便利贴候选为视觉中心；调试参数与内部数据仍在，但不再污染产品面。功能对拍现网行为，**禁止借机改坏管线语义**。

## 1. 为什么现在做视觉（动机）

| 现状 | 问题 |
|------|------|
| Tab 平铺、管线模拟器仍在 | Live 已跑通；模拟器冗余；入口顺序不像使用流 |
| 语言 prefs 整块大 Card | 纵向浪费；不像壳，像问卷 |
| Live 产品控件与 VAD/STT 旋钮混排 | 看不出「最终用户会看见什么」 |
| 候选卡是普通 `border` 列表 | 没有产品符号；无法预演正式 UI |
| `primary` 仍为 shadcn 近黑 | 与「主题色黄色」不符 |
| `packages/ui` 组件极少 | 手写 HTML/div 堆砌，观感廉价 |

Playground **同时是最终 app 的试炼场**：允许暴露用户不可调参数与内部数据，但 **UI 不允许糊弄**。视觉层在此定稿的组件（尤其便利贴候选卡）应可迁入 `apps/web` / 日后桌面壳。

## 2. 非目标（硬性）

- **不改**：会话状态机、STT batch/realtime 路径、聚合/`pauseMs`、LLM 请求时机、候选 schema（3 条或 `[]`）、声纹 embedding 算法与存储。
- **不做**：Electron Island、透明悬浮窗、假桌面预演（见头脑风暴；正式桌面另开）。
- **不借机**：无关重构、文档大扫除、评测/prompt 改动。
- **不满屏纸噪点纹理**（易脏、易闪）；纸感靠色、层叠阴影、便利贴工艺表达。

## 3. 信息架构

### 3.1 心智模型

| 层 | 角色 | 视觉要求 |
|----|------|----------|
| **产品主舞台** | 实时会话的主栏 + 声纹向导主流程 | 接近最终用户所见；精致、纸感、少控件 |
| **实验室** | VAD 检测、直连 API；Live/声纹的「高级/调试」折叠区 | 同纸壳与黄 primary；**密度更高**；分区清晰，可用 Collapsible |

### 3.2 Tab

删除 **管线模拟器**（含路由、入口、死代码）。

| 顺序 | Tab | 默认 |
|------|-----|------|
| 1 | 实时会话 | 已有声纹 embedding 时默认打开 |
| 2 | 声纹录入 | **无**声纹时默认打开 |
| 3 | VAD 检测 | — |
| 4 | 直连 API | — |

首屏：读 IndexedDB（或现有 enrollment 存储）判断是否已有 user embedding → 选默认 tab。缺声纹时 Live 工具条须有明确 CTA 导向声纹 tab。

### 3.3 全局壳

```text
┌─ Header ─────────────────────────────────────────────┐
│ KiboTalk 试用场     [语言摘要 ▾ Popover]  [可选主题]   │
├─ Tabs ───────────────────────────────────────────────┤
│ 实时会话 | 声纹录入 | VAD 检测 | 直连 API              │
└──────────────────────────────────────────────────────┘
```

- **语言设置**：顶栏摘要（如 `日语 · 释义中文 · 初级`）+ **Popover** 内编辑；`liveSessionRunning` 时 disabled（与现逻辑一致）。
- 去掉 tabs 上方整块语言 Card。
- 首次 `languagesConfirmed === false` 的 onboarding 保留，视觉对齐纸感壳（仍一页确认）。

## 4. 视觉系统（本 spec 核心）

### 4.1 品牌与纸感

| Token / 概念 | 要求 |
|--------------|------|
| **`--primary`** | 墨色 ink（CTA / 主按钮）；**黄色只留给便利贴**（用户覆盖：不要黄 CTA） |
| **`--sticky` / sticky 表面** | **另一套**经典便利贴黄（纸感）；禁止与 primary 共用同一 hex |
| **页面底** | 干净浅灰 / 白；**不要**土黄 / 牛皮 kraft 整页底 |
| **叠纸层次** | 表面像叠放的纸：轻阴影、微边界；卡片勿用厚玻璃拟态 / 重多阴影 |
| **暗色** | **暖色暗色纸**（夜书桌），不是简单 cool invert；sticky 仍保持亮黄+深墨 |
| **排版** | 统一非衬线；略松行距；少用大圆角药丸堆；中文 UI 文案保持 |

质地层级（已决 **A**）：**色 + 层叠 + 便利贴折角/纸边工艺**。不做满屏纤维噪点；不做撕裂边/胶带/印章等廉价「手账贴纸风」。

### 4.2 便利贴候选卡（产品符号）

替换现有朴素 `ReplyCandidateCard` 默认外观为 **StickyNote** 视觉（schema 不变：`targetText` / `meaning` / `segments`…）。

**必须做到的观感：**

- 黄色纸面；**折角或精致纸边**（至少一角折起或等效纸工艺）
- 轻阴影、可有 **1–2° 微错位**（每张略不同）
- 内容可读：目标语为主，meaning 次之；日语 `segments`/ruby 保留
- **禁止**：用更高的卡完全盖住下层文字（见 §5.1）
- **必须有动画**（见 §4.4）：入场、轮次顶替、旧轮弱化都要过渡，不能「闪现 / 瞬切」

提供两种密度：

| 变体 | 用途 |
|------|------|
| `sticky`（默认） | Live 主舞台 |
| `compact` | 对话侧栏时间轴一行摘要（可保留现逻辑） |

组件放 `packages/ui` 或 playground `components/` 但 **视觉 token 必须来自共享 CSS 变量**，便于迁入正式 app。

### 4.3 组件库优先（硬性工程约束）

开发**基于已安装的 shadcn / `@kibotalk/ui`**，不要在「太基础」的层级上重造轮子。

| 可以 | 不可以 |
|------|--------|
| 用 `Button` / `Card` / `Sheet` / `Select`… 拼页面 | 再写一个平行的 `MyButton`、`FancyCard` 去包一层原生 `<button>` / 手搓弹层 |
| **直接改** `packages/ui` 里对应组件的变体、尺寸、圆角、颜色 token（例如改 `button.tsx` 的 `cva` variants） | 在 playground 里用 `className` 堆出「另一个按钮体系」绕过设计系统 |
| 为产品符号新增**真正新的**组件（如 `StickyNote`）——库里没有等价物时 | 把 StickyNote 做成又一套 Button/Badge/Input |
| 缺组件 → 先 `shadcn add` 进 `packages/ui` 再使用 | 「先用 div 顶着，以后再说」 |

原则一句话：**样式与行为的源头在 `packages/ui`；playground 只组合，不分叉。** 需要黄 primary、纸感圆角、焦点环——改 token / 改组件源文件，而不是复制一份改。

补齐常用套件（Select、Popover、Sheet、Collapsible、ScrollArea、Slider、Switch、Progress、Tooltip、Skeleton、Dialog、DropdownMenu、Sonner、Accordion 等；按 repo `components.json` 装入 `packages/ui`）。

现有：Button、Card、Badge、Input、Label、Textarea、Tabs、Separator。

装完后更新包导出与（若 AGENTS/README 有组件列表）保持同步。

### 4.4 动效（便利贴 · 苹果式自然过渡）

便利贴列是主舞台，**静态贴上不够**；动效是验收的一部分。参照苹果通知中心 / 系统 sheet 的感觉：**跟手、有重量、减速自然**，不要线性闪切或夸张弹跳。

| 场景 | 期望 |
|------|------|
| **新轮入场** | 从上方或轻微缩放+淡入落入；三张可短错峰（几十 ms），勿整列瞬现 |
| **旧轮下移 / 顶替** | 布局变化用平滑位移（spring 或 cubic-bezier 减速）；与通知叠放类似 |
| **旧轮弱化** | opacity / 纸色 / 微 scale **渐变**到次级态，不是一步到位 |
| **离开可视 N 轮** | 淡出或下滑离开后再卸载；避免突然消失导致跳动 |
| **空态 ↔ 有内容** | 纸位与真卡之间过渡自然 |
| **交互反馈**（若可点） | 按下轻微下压/阴影变化，松手回弹短促 |

**质感约束（苹果向）：**

- 优先 **spring / 带过冲极小的减速曲线**；时长大约 **280–450ms** 量级（入场可略长，弱化可略短）；避免 >700ms 拖沓。
- **共享元素感**：下移的旧轮与新轮插入应像同一物理层在让位，而不是两套 opacity 交叉溶解了事。
- 尊重 `prefers-reduced-motion`：减动效时改为短淡入或直接到位，不卡功能。
- 技术选型不锁死（CSS transitions、WAAPI、`motion` / soft spring 均可）；但**曲线与时长须统一**，禁止每张卡各写各的 `ease-in` 闪一下。

侧栏 Sheet / Collapsible / Popover 尽量用 shadcn 自带过渡，不另造一套弹窗动画语言。

## 5. Live 布局（视觉结构）

### 5.1 主舞台：通知中心式便利贴列

主栏**视觉中心只有候选便利贴**（不是对话时间轴）。

```text
┌ 工具条 ──────────────────────────────────────────┐
│ 开始/停止 · 状态 pill · STT 路径 · 缺声纹 CTA …   │
├ 便利贴列（ScrollArea）───────────────────────────┤
│ ┌ sticky 新轮（内含 3 条候选）┐                   │
│ └────────────────────────────┘                   │
│ ┌ sticky 旧轮 …  ┐  ← 降对比/透明，字仍完整可读   │
│ └ …              ┘                               │
└──────────────────────────────────────────────────┘
```

| 规则 | 说明 |
|------|------|
| 一轮内部 | **一张便利贴内竖排三条候选**（非三张纸、非横排） |
| 多轮 | 像通知中心：**最新轮在上**，旧轮被顶到下方 |
| 可见轮数 | 用户可设最多最近 **N 轮**（playground 控件放 **调试侧栏**）；超出丢弃或不再渲染最旧轮 |
| 旧轮区分 | 透明度 / 纸色变淡 / 缩放微弱；**文字不得被上层遮挡至不可读** |
| 错位 | 允许轻微旋转/偏移；忌大扇形挡字 |
| 空态 | **一张**浅纸位 + 三条骨架线 + 简短说明（未开始 / 等待建议） |
| 流式 | 纸骨架置顶（可与旧轮并存）；避免布局狂跳 |
| `[]` / 失败 / 请求中 | **保留**上一轮已提交候选（与产品 F04 一致）；勿先清空主舞台 |

新轮到达时滚动位置：**默认滚到顶部**（最新轮），除非用户正在上翻阅读旧轮（实现时可先做「总是贴顶」，再加「阅读中不抢焦」若有余力）。

### 5.2 对话记录（次要，但是产品面）

| 视口 | 形态 |
|------|------|
| 宽屏 | **左侧可折叠**侧栏 |
| 窄屏 | **抽屉 / Sheet** |

默认可不展开；展开后展示 turn 时间轴（含 draft 行若有）。**不要**把对话做成主栏中心。

### 5.3 调试侧栏（实验室，Live 内）

| 视口 | 形态 |
|------|------|
| 宽屏 | **右侧可折叠**侧栏（默认可收起为图标条） |
| 窄屏 | Sheet |

内容：现有 VAD / 合并 / STT provider·mode / 阈值等；**最多 N 轮**设置；内部状态日志级信息。折叠后主舞台应仍完整可用。

宽屏默认结构：

```text
[ 对话｜可收 ] [ 工具条 + 便利贴列 ] [ 调试｜可收 ]
```

### 5.4 工具条

主栏顶部细条（非全局 Header、不塞进对话栏）：开始/停止、管线状态、必要 pill、缺声纹 CTA。会话控制折叠对话栏时仍可见。

## 6. 声纹页（产品第一步）

声纹是欢迎/语言确认之后、正式会话前的 **第一件产品事**——须 **便于完成**，并保留一点纸感风格化。

**向导（已决 A）：**

1. **说明** — 为什么要录、大概多久  
2. **录入** — 按 `conversationLang` 口令朗读；大主按钮；进度清晰（Progress）  
3. **完成确认** — 成功态；可重录；引导去实时会话  

阈值、原始 similarity、自由说话校验等 **折叠进「高级」**（实验室密度）。本轮 **不强制**「录完必须校验通过才算 enrolled」（校验可留在高级区，行为可与现页对齐但不挡主路径完成）。

## 7. VAD / 直连 API

- 同一纸壳、黄 primary、顶栏语言摘要。
- 保持调试密度；用 Section + Collapsible 分开「操作」与「原始数据/日志」。
- **不大改**信息架构与功能；换肤 + 组件化为主。

## 9. 实现提示（非绑定）

- Token 落在 playground `index.css`（或日后抽到 `packages/ui` 主题），`--sticky*` 进 `@theme`；黄 primary **改 CSS 变量 + Button 变体**，不要新建 `YellowButton`。
- Live 拆子组件：`SessionToolbar`、`StickyCandidateStack`、`TranscriptPanel`、`DebugPanel`，避免单文件继续膨胀。
- 候选历史：在现有 `latestCandidates` 之上维护「轮次栈」（每轮 0 或 3 条），UI 只读栈顶 N 轮；列表用可动画的 key（轮次 id），便于布局动画。
- 动效：优先一套共享 easing token（如 `--ease-out-soft` / spring 配置）；Sticky 栈集中在一处实现，忌散落 magic number。
- deslop / code-simplifier 收尾；针对性 typecheck；不主动扩测试除非逻辑回归需要。

## 10. 与正式产品 / 桌面的边界

| | 本轮 Playground | 正式 Web / 桌面 |
|--|-----------------|-----------------|
| 便利贴卡 | **定视觉与组件** | 复用 |
| 通知中心多轮 | Playground 先做；N 为调试设置 | 产品是否暴露 N 另议 |
| Island | **Playground 预演**（黄色图标岛：转写 / AI 提示开关 + 状态） | 见头脑风暴；正式桌面复用 |
| 调试侧栏 | 保留 | 正式壳不出现 |
